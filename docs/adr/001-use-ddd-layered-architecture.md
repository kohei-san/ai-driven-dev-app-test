# ADR 001: 勤怠管理システムにおけるDDDレイヤードアーキテクチャとAI駆動開発ガードレールの採用

* **ステータス:** 承認済み（Accepted）
* **作成日:** 2026-11-16
* **対象システム:** 勤怠管理システム（Attendance Management System）

---

## 1. コンテキスト（背景と課題）

本プロジェクトは、AIコーディングエージェント（Claude Code）を活用したAI駆動開発（AIDD）の実践および、将来的な機能拡張（有給申請・シフト管理・DB永続化への移行）に耐えうる保守性の高い設計を目指して構築している。

AIエージェントによる高速なコード生成には、以下のリスクが伴う。
1. **アーキテクチャの崩壊:** AIが実装のしやすさを優先し、ドメインロジック内にフレームワーク（Next.js）や永続化層（DB）への直接依存を混入させるリスク。
2. **ビジネスルールの散逸:** 残業時間の計算や二重打刻防止などの重要な業務ルールが、UIコンポーネントやAPIハンドラに分散するリスク。
3. **レビュー負荷の増大:** 生成スピードに対して人間の目視確認だけでは品質担保が追いつかなくなるリスク。

## 2. 決定事項（Decision）

上記の課題に対し、以下の技術選定および開発プロセスを採用することを決定した。

1. **フルスタック TypeScript（strictモード）の採用**
   * コンパイル時の静的型検査をAIの自己修正ループ（自律デバッグ）のフィードバック機構として活用するため。
2. **DDD（ドメイン駆動設計）＋ レイヤードアーキテクチャの採用**
   * `domain` / `application` / `infrastructure` / `presentation` の4層に分離し、依存の方向を「外側 → 内側」の一方向に制限する。
   * `domain` 層は外部ライブラリに一切依存しない純粋なTypeScriptのみで記述する。
3. **機械的なアーキテクチャ境界チェックの導入（`dependency-cruiser`）**
   * ルールファイル（`CLAUDE.md`）での自然言語指示だけでなく、静的解析ツールにより層違反をCI上で自動検知・ブロックする。
4. **TDD（テスト駆動開発）＋ Issue駆動 PR ベース開発**
   * `Vitest` を用い、実装前にテスト（Red）を作成してから実装（Green）を行うサイクルを 1 Issue = 1 PR の粒度で回す。
   * GitHub Actions によるCI検証に加え、`anthropics/claude-code-action` によるAI一次コードレビューを組み込む。

## 3. 検討した代替案（Alternatives Considered）

* **代替案A: Next.js の API Route / Server Actions に直接ロジックを書く構成（トランザクションスクリプト）**
  * *却下理由:* 初期構築は最速だが、業務ルール（時刻整合性・残業計算・二重打刻防止）が増えるにつれてテストが困難になり、AIによる改修時のデグレードリスクが高まるため。
* **代替案B: 全UseCaseクラスにインターフェース（`I〇〇UseCase`）を定義する厳格なクリーンアーキテクチャ**
  * *却下理由:* リポジトリ層にはDB切り替えと依存性逆転のためインターフェース（`IAttendanceRepository`）を設けたが、UseCase層はTypeScriptの構造的部分型とVitestのスパイ機能（`vi.spyOn`）で十分にモック化が可能であり、過剰なファイル分割による可読性低下を避けるため採用しなかった。

## 4. 結果と影響（Consequences）

* **メリット:**
  * ドメインモデルの単体テストが高速かつ独立して実行でき、業務ルールの正当性を担保できた。
  * `dependency-cruiser` と CI の組み合わせにより、AIが生成したコードの設計逸脱をマージ前に確実に防ぐことができた。
* **トレードオフ・今後の課題:**
  * 小規模な機能追加でも複数ファイルの作成が必要になるが、`CLAUDE.md` に命名規則と手順を明文化することでAIが迷わずボイラープレートを生成できるため、開発速度の低下は最小限に抑えられている。
  * 現在は `InMemoryAttendanceRepository` で永続化しているが、リポジトリインターフェースが分離されているため、ドメイン層を一切変更せずに PostgreSQL（Prisma）等へ差し替え可能である。
