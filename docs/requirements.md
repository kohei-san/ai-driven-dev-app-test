## 1. システム概要

### 1.1 目的

従業員が Web ブラウザから **出勤・退勤を打刻** し、日々の **実働時間・残業時間を自動計算** して確認できるシステムを提供する。

本プロジェクトは、機能そのものに加えて次の 2 点を実証することを目的とする。

1. **DDD の実践** — 勤怠に関する業務ルールをドメイン層に集約し、UI・API・永続化の技術から独立させる。
2. **AI 駆動開発（AIDD）の実践** — 本書と [CLAUDE.md](../CLAUDE.md) を AI エージェントへの「仕様」として与え、TDD でテスト先行の実装を進める。

### 1.2 スコープ（初期フェーズ MVP）

| 区分 | 対象 | 備考 |
| --- | --- | --- |
| ✅ 対象 | 出勤打刻 | |
| ✅ 対象 | 退勤打刻（休憩時間の入力を含む） | |
| ✅ 対象 | 当日の勤怠状況確認 | 未出勤 / 出勤中 / 退勤済 |
| ✅ 対象 | 勤怠履歴一覧の取得 | 期間指定、実働・残業時間付き |
| ✅ 対象 | インメモリ永続化 | `InMemoryAttendanceRepository` |
| ❌ 対象外 | 認証・認可 | 固定 ID `emp-001` または `x-employee-id` ヘッダで代替 |
| ❌ 対象外 | DB 永続化 | 将来 `PrismaAttendanceRepository` に差し替え |
| ❌ 対象外 | 打刻の修正・削除、承認ワークフロー | |
| ❌ 対象外 | 複数回の休憩打刻（休憩開始/終了） | 退勤時に合計休憩時間を入力する方式 |
| ❌ 対象外 | 深夜・休日割増、変形労働時間制 | 残業は「1 日 480 分超過分」のみ |
| ❌ 対象外 | 従業員マスタ管理 | 従業員 ID は文字列として受け付ける |

### 1.3 前提・制約

| # | 前提 |
| --- | --- |
| P-1 | タイムゾーンは **日本標準時（JST, UTC+9）** 固定とする。 |
| P-2 | 打刻時刻は **サーバーの現在時刻** を採用し、クライアントからは送らない（改ざん防止）。 |
| P-3 | 時間の計算単位は **分**。秒以下は切り捨てる。 |
| P-4 | 営業日は **出勤時刻の JST 日付** とする（日付をまたいで退勤しても、出勤日の勤怠として扱う）。 |
| P-5 | MVP の永続化はインメモリのため、サーバー再起動でデータは消える。 |

### 1.4 アクター

| アクター | 説明 |
| --- | --- |
| 従業員 | 自分の出勤・退勤を打刻し、自分の勤怠を閲覧する。MVP では唯一のアクター。 |

## 2. 機能要件

| ID | 機能 | 概要 | 対応ユースケース |
| --- | --- | --- | --- |
| F-01 | 出勤打刻 | 現在時刻で出勤を記録し、勤怠ステータスを「出勤中」にする | `ClockInUseCase` |
| F-02 | 退勤打刻 | 現在時刻で退勤を記録し、休憩時間を登録して実働・残業時間を確定する | `ClockOutUseCase` |
| F-03 | 当日の勤怠状況確認 | 本日の勤怠ステータスと打刻時刻を表示する | `GetTodayAttendanceUseCase` |
| F-04 | 勤怠履歴一覧の取得 | 指定期間の勤怠レコードを一覧で取得する | `GetAttendanceListUseCase` |

### F-01 出勤打刻

| 項目 | 内容 |
| --- | --- |
| 入力 | 従業員 ID（ヘッダ） |
| 処理 | サーバー現在時刻を出勤時刻とし、その JST 日付を営業日として勤怠レコードを新規作成する |
| 出力 | 作成された勤怠レコード（ステータス: 出勤中） |
| 主な異常系 | 同一営業日に出勤中のレコードが存在する → 二重打刻エラー |

### F-02 退勤打刻

| 項目 | 内容 |
| --- | --- |
| 入力 | 従業員 ID（ヘッダ）、休憩時間（分, 任意。省略時 60 分） |
| 処理 | 従業員の出勤中レコードに、サーバー現在時刻を退勤時刻として記録し、実働時間・残業時間を算出する |
| 出力 | 更新された勤怠レコード（ステータス: 退勤済、実働時間・残業時間付き） |
| 主な異常系 | 出勤中レコードがない / 退勤時刻が出勤時刻以前 / 休憩時間が不正 |

### F-03 当日の勤怠状況確認

| 項目 | 内容 |
| --- | --- |
| 入力 | 従業員 ID（ヘッダ） |
| 処理 | 本日（JST）の営業日に属する勤怠レコードのうち最新のものを取得し、ステータスを判定する |
| 出力 | ステータス（未出勤 / 出勤中 / 退勤済）と、存在すれば勤怠レコード |

### F-04 勤怠履歴一覧の取得

| 項目 | 内容 |
| --- | --- |
| 入力 | 従業員 ID（ヘッダ）、期間 `from`〜`to`（任意。省略時は当月 1 日〜本日） |
| 処理 | 期間内の勤怠レコードを営業日の降順で取得する |
| 出力 | 勤怠レコードの配列と、期間内の実働時間・残業時間の合計 |
| 主な異常系 | 日付形式が不正 / `from` > `to` / 期間が 93 日を超える |

## 3. 業務ルール・バリデーション要件（受け入れ条件）

CLAUDE.md の「勤怠管理のドメインルール」を、テストケースにそのまま落とせる受け入れ条件（Given / When / Then）に具体化する。
各ルールの **実装責務の所在**（どの値オブジェクト・エンティティ・サービスが守るか）は [ドメインモデル設計書](./domain-model.md) を参照。

### BR-01 時刻の整合性

> 退勤時刻は出勤時刻より **後** でなければならない。

| AC | Given | When | Then |
| --- | --- | --- | --- |
| AC-01-1 | 09:00 に出勤済み | 18:00 に退勤打刻 | 退勤が記録される |
| AC-01-2 | 09:00 に出勤済み | 09:00（同時刻）に退勤打刻 | `INVALID_CLOCK_OUT_TIME` エラー。レコードは変更されない |
| AC-01-3 | 09:00 に出勤済み | 08:59 に退勤打刻 | `INVALID_CLOCK_OUT_TIME` エラー |
| AC-01-4 | 11/15 22:00 に出勤済み | 11/16 06:00 に退勤打刻 | 退勤が記録され、営業日は **11/15** のまま |

### BR-02 二重打刻の防止

> 同一従業員・同一営業日に「出勤中（未退勤）」のレコードがある場合、新規の出勤打刻は許可しない。

| AC | Given | When | Then |
| --- | --- | --- | --- |
| AC-02-1 | 本日の勤怠レコードなし | 出勤打刻 | 出勤中レコードが作成される |
| AC-02-2 | 本日 09:00 に出勤し、未退勤 | 再度出勤打刻 | `ALREADY_CLOCKED_IN` エラー。レコードは増えない |
| AC-02-3 | 本日 09:00 出勤 → 12:00 退勤済み | 13:00 に出勤打刻 | 新しい出勤中レコードが作成される（同日 2 件目） |
| AC-02-4 | 従業員 A が本日出勤中 | 従業員 B が出勤打刻 | B の出勤中レコードが作成される（従業員ごとに独立） |
| AC-02-5 | 出勤中レコードなし | 退勤打刻 | `NOT_CLOCKED_IN` エラー |

### BR-03 実働時間と残業計算

> 実働時間 ＝（退勤時刻 − 出勤時刻）− 休憩時間
> 残業時間 ＝ max(0, 実働時間 − 所定労働時間 480 分)

| AC | 出勤 | 退勤 | 休憩 | 期待: 実働 | 期待: 残業 |
| --- | --- | --- | --- | --- | --- |
| AC-03-1 | 09:00 | 18:00 | 60 分 | 480 分（8:00） | 0 分 |
| AC-03-2 | 09:00 | 20:30 | 60 分 | 630 分（10:30） | 150 分（2:30） |
| AC-03-3 | 09:00 | 13:00 | 0 分 | 240 分（4:00） | 0 分 |
| AC-03-4 | 09:00 | 18:01 | 60 分 | 481 分 | 1 分（境界値） |
| AC-03-5 | 09:00:00 | 18:00:59 | 60 分 | 480 分（秒は切り捨て） | 0 分 |

### BR-04 休憩時間のバリデーション

| AC | Given | When | Then |
| --- | --- | --- | --- |
| AC-04-1 | — | 休憩時間に負の値（-1）を指定 | `INVALID_BREAK_DURATION` エラー |
| AC-04-2 | — | 休憩時間に整数以外（30.5）を指定 | `INVALID_BREAK_DURATION` エラー |
| AC-04-3 | 09:00 出勤 | 10:00 に休憩 60 分で退勤 | `INVALID_BREAK_DURATION` エラー（休憩は拘束時間 **未満** であること） |
| AC-04-4 | — | 休憩時間を省略して退勤 | 休憩 60 分として計算される |

### BR-05 認証スコープ（仮置き）

| AC | Given | When | Then |
| --- | --- | --- | --- |
| AC-05-1 | — | `x-employee-id: emp-002` ヘッダ付きでリクエスト | `emp-002` として処理される |
| AC-05-2 | — | ヘッダなしでリクエスト | 既定のテスト従業員 `emp-001` として処理される |
| AC-05-3 | — | ヘッダが空文字・空白のみ | `emp-001` として処理される |
| AC-05-4 | — | ヘッダが 65 文字以上、または英数字・`-`・`_` 以外を含む | `VALIDATION_ERROR` エラー |

## 4. 画面仕様

### 4.1 画面構成

MVP は **1 画面（`/`）** のみ。上部に打刻ボタンエリア、下部に勤怠一覧テーブルを配置する。

```text
┌──────────────────────────────────────────────────────────────┐
│  勤怠管理                                   従業員ID: emp-001 │
├──────────────────────────────────────────────────────────────┤
│  ■ 打刻エリア                                                 │
│                                                              │
│    2026/11/16 (月)  14:32                                     │
│    本日のステータス:  [ 出勤中 ]   出勤 09:02                  │
│                                                              │
│    [  出勤  ]   休憩 [ 60 ] 分  [  退勤  ]                    │
│                                                              │
│    ⚠ エラーメッセージ表示領域                                  │
├──────────────────────────────────────────────────────────────┤
│  ■ 勤怠一覧            期間 [2026-11-01] 〜 [2026-11-16] [表示] │
│                                                              │
│  営業日     | 出勤  | 退勤  | 休憩  | 実働  | 残業  | 状態    │
│  ---------- | ----- | ----- | ----- | ----- | ----- | ------- │
│  11/16 (月) | 09:02 |   -   |   -   |   -   |   -   | 出勤中  │
│  11/14 (金) | 09:00 | 20:30 | 1:00  | 10:30 | 2:30  | 退勤済  │
│  11/13 (木) | 08:55 | 18:00 | 1:00  | 8:05  | 0:05  | 退勤済  │
│  ---------- | ----- | ----- | ----- | ----- | ----- | ------- │
│  合計                       |       | 18:35 | 2:35  |         │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 打刻ボタンエリア

| 要素 | 仕様 |
| --- | --- |
| 現在日時 | 1 分ごとに更新して表示（表示のみ。打刻時刻はサーバー側で決定） |
| 本日のステータス | F-03 の結果を表示。「未出勤」「出勤中」「退勤済」のバッジ |
| 出勤ボタン | ステータスが **未出勤 / 退勤済** のとき有効。押下で F-01 を呼び出す |
| 休憩時間入力 | 0 以上の整数（分）、初期値 60。ステータスが **出勤中** のとき有効 |
| 退勤ボタン | ステータスが **出勤中** のとき有効。押下で F-02 を呼び出す |
| エラー表示 | API のエラーメッセージ（`error.message`）を表示する |
| 打刻成功後 | 本日のステータスと勤怠一覧を再取得する |

> ボタンの活性制御は UX のための補助であり、**業務ルールの最終判定は常にドメイン層で行う**（UI を迂回した API 直接呼び出しでも BR-01〜04 が守られる）。

### 4.3 勤怠一覧テーブル

| 列 | 表示形式 | 備考 |
| --- | --- | --- |
| 営業日 | `MM/DD (曜)` | 降順 |
| 出勤 | `HH:mm` | |
| 退勤 | `HH:mm` / `-` | 出勤中は `-` |
| 休憩 | `H:mm` / `-` | |
| 実働 | `H:mm` / `-` | |
| 残業 | `H:mm` / `-` | 0 より大きい場合は強調表示 |
| 状態 | 出勤中 / 退勤済 | |
| 合計行 | 実働・残業の期間合計 | 退勤済レコードのみ集計 |

## 5. API エンドポイント一覧

### 5.1 共通仕様

| 項目 | 内容 |
| --- | --- |
| ベースパス | `/api/attendances` |
| 形式 | JSON（`Content-Type: application/json`） |
| 従業員の識別 | リクエストヘッダ `x-employee-id`（省略時 `emp-001`） |
| 日時の表現 | ISO 8601、JST オフセット付き（例: `2026-11-16T09:02:00+09:00`） |
| 日付の表現 | `YYYY-MM-DD`（例: `2026-11-16`） |
| エラー形式 | `{ "error": { "code": "ALREADY_CLOCKED_IN", "message": "本日はすでに出勤中です" } }` |

### 5.2 エンドポイント

| # | メソッド | パス | 機能 | リクエスト | 成功時 |
| --- | --- | --- | --- | --- | --- |
| 1 | `POST` | `/api/attendances/clock-in` | F-01 出勤打刻 | ボディなし | `201` `AttendanceDto` |
| 2 | `POST` | `/api/attendances/clock-out` | F-02 退勤打刻 | `{ "breakMinutes"?: number }` | `200` `AttendanceDto` |
| 3 | `GET` | `/api/attendances/today` | F-03 当日の状況 | なし | `200` `TodayAttendanceDto` |
| 4 | `GET` | `/api/attendances?from=YYYY-MM-DD&to=YYYY-MM-DD` | F-04 履歴一覧 | クエリ（任意） | `200` `AttendanceListDto` |

DTO の詳細は [ドメインモデル設計書 §6](./domain-model.md#6-ユースケース) を参照。

#### レスポンス例: `POST /api/attendances/clock-out`

```json
{
  "id": "att-7f3c...",
  "employeeId": "emp-001",
  "businessDate": "2026-11-14",
  "clockInAt": "2026-11-14T09:00:00+09:00",
  "clockOutAt": "2026-11-14T20:30:00+09:00",
  "breakMinutes": 60,
  "workMinutes": 630,
  "overtimeMinutes": 150,
  "status": "FINISHED"
}
```

### 5.3 エラーコード一覧

| HTTP | コード | 発生条件 | 対応ルール |
| --- | --- | --- | --- |
| `400` | `VALIDATION_ERROR` | 従業員 ID・日付・期間・リクエストボディの形式不正 | BR-05, F-04 |
| `400` | `INVALID_BREAK_DURATION` | 休憩時間が負数・非整数、または拘束時間以上 | BR-04 |
| `409` | `ALREADY_CLOCKED_IN` | 同一営業日に出勤中レコードがある状態で出勤打刻 | BR-02 |
| `409` | `NOT_CLOCKED_IN` | 出勤中レコードがない状態で退勤打刻 | BR-02 |
| `422` | `INVALID_CLOCK_OUT_TIME` | 退勤時刻が出勤時刻以前 | BR-01 |
| `500` | `INTERNAL_ERROR` | 想定外のエラー | — |

> ドメイン層は HTTP を知らない。ドメイン例外（`DomainError` の派生）を `app` 層の API Route で上表の HTTP ステータスに変換する。

## 6. 非機能要件（MVP）

| 区分 | 要件 |
| --- | --- |
| 保守性 | 層間の依存方向を `npm run arch:check`（dependency-cruiser）で CI 上で強制する |
| 品質 | ドメイン層・アプリケーション層は Vitest で単体テストを先行作成する（TDD） |
| 品質ゲート | `npx next typegen && npx tsc --noEmit` / `npm run arch:check` / `npx vitest run` / `npm run lint` がすべてエラーゼロ |
| 型安全 | TypeScript strict モード、`any` 禁止 |
| テスト容易性 | 現在時刻は `IClock` 経由で取得し、テストで任意の時刻を注入できること |
| 拡張性 | リポジトリ実装の差し替え（InMemory → Prisma）でドメイン・アプリケーション層に変更が出ないこと |
